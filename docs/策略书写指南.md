# 高周期策略书写指南

> 适用：`vnpy_domestic`（vnpy 4.3 + vnpy_domestic + akshare datafeed）；
> 示例策略（`dynamic_donchian_strategy.py`）在 `模拟盘simnow/strategies` 部署目录；
> 目标：写 15/30/60 分钟这类**高周期** CTA 策略时，保证它**能初始化成功、能真正交易**

---

## 0. 一句话总结

> 高周期策略在模拟盘的死法只有一个：**`load_bar` 拿不到够用的历史数据**，
> 于是 `ArrayManager` 永远 `inited=False`，策略"初始化成功"却一笔不交易，还不报错。

解决方式也只有一个：**预热自己去 akshare 拉该周期的 K，直通 `on_bg_bar`**，不要指望 `load_bar`。

---

## 1. 先搞清楚数据链路

```
实时阶段（每个 tick）
   on_tick(tick)
     └─ MyBarGenerator.update_tick ──► 合成 1 分钟 bar
          └─ MyBarGenerator.update_bar ──► 按 bg_window 聚合成 15/60 分钟 bar
               └─ on_bg_bar(bar)   ◄── 你的策略逻辑写在这里
```

**注意 `update_tick` 和 `update_bar` 是两段不同的代码路径**：

| 方法 | 输入 | 输出 | 触发条件 |
|---|---|---|---|
| `update_tick` | tick | 1 分钟 bar | 分钟数变化 |
| `update_bar` | 1 分钟 bar | `bg_window` 分钟 bar | `(bar.minute + 1) % bg_window == 0` |

### 1.1 `bg_window` 的硬约束

```python
if not (bar.datetime.minute + 1) % self.window:   # 只有这一行
```

- **`bg_window` 必须整除 60**：`1, 2, 3, 4, 5, 6, 10, 12, 15, 20, 30, 60`
- **`bg_window > 60` 永远不触发**（`minute+1` 最大 60，`% 120` 永不等于 0）→ 2 小时/4 小时必须自己写聚合器
- **`bg_window = 1`** 等价于直通：每根进来立刻 emit

### 1.2 `load_bar` 在模拟盘怎么取数

`CtaEngine.load_bar()`（`vnpy_ctastrategy/engine.py:547`）的顺序是：

```
1. 合约有 history_data 标记 → gateway.query_history()   ← CTP 没有，永远空
2. query_bar_from_datafeed()                            ← 走 vt_setting.json 的 datafeed
3. self.database.load_bar_data()                        ← vnpy 自己的 bar_data 表
```

你的 `vt_setting.json` 是 `"datafeed.name": "akshare"` → 走 `vnpy_domestic/trader/vnpy_akshare.py`。

**而这个 datafeed 只认 `Interval.MINUTE`，只返回 1023 根 1 分钟 K。**

## 2. 核心坑：为什么高周期策略"初始化成功但不交易"

`ArrayManager(size=n2+30)` 需要 `n2+30` 根才 `inited`。默认 `n2=180` → **需要 210 根**。

| 预热来源 | 能拿到多少 | 够 210 根吗 |
|---|---|---|
| datafeed `vnpy_akshare`（1 分钟） | 1023 根 1m ≈ 3 个交易日 | 聚合到 15m 只剩 **~60 根** ❌ |
| database `bar_data` | 你的库里 **是空的**（`~/.vntrader/database.db` 0 行） | ❌ |
| gateway | CTP 不提供历史 | ❌ |

结果：

```
on_init() 跑完 → CtaEngine 把 strategy.inited = True（engine.py:704）
             → GUI 显示"已初始化 ✅"
             → 但策略内部 am.inited = False
             → on_bg_bar 里 if not am.inited: return
             → 一笔都不交易，日志里也没有任何错误
```

**这个状态极难发现**，因为框架认为你已经初始化好了。

## 3. 标准写法（模板）

### 3.1 参数

```python
class MyStrategy(CtaTemplate):
    n1: int = 15
    n2: int = 180
    bg_window: int = 60              # 目标周期（分钟）
    warmup_source: str = "database"  # database / akshare / auto
    warmup_bars: int = 300           # 预热根数（代码会自动 >= n2+30）

    parameters = ["n1", "n2", "bg_window", "fixed_size",
                  "warmup_source", "warmup_bars"]
```

> `warmup_source` 默认 `"database"`，**模拟盘配置里必须显式写 `"akshare"`**。
> 这样回测（用内存数据）和实盘（用 akshare）互不干扰。

### 3.2 `on_init`：先 akshare，失败再退回数据库

```python
def on_init(self) -> None:
    self.am = ArrayManager(size=self.n2 + 30)
    self.bg = MyBarGenerator(self.on_bar, self.bg_window, self.on_bg_bar,
                             enable_trading_filter=True)

    if not self._warmup():
        self.write_log(
            f"⚠️ 预热不足，需再等 {self.n2 + 30 - self.am.count} 根 "
            f"{self.bg_window} 分钟 K 才会开始交易"
        )
    self.write_log(f"初始化结束 am={self.am.count}/{self.am.size} "
                   f"inited={self.am.inited}")

def _warmup(self) -> bool:
    if self.warmup_source in ("akshare", "auto"):
        if self._warmup_from_akshare():
            return True
        self.write_log("akshare 预热失败，回退数据库")
    self.load_bar(self._load_bar_days(), callback=self.bg.update_bar)
    return self.am.inited
```

### 3.3 akshare 预热：**直通 `on_bg_bar`，不要再聚合**

```python
def _warmup_from_akshare(self) -> bool:
    import akshare as ak
    symbol, exchange = self._split_vt_symbol()
    sina = self._sina_symbol(symbol)                       # SM701 -> sm2701

    df = ak.futures_zh_minute_sina(symbol=sina, period=str(self.bg_window))
    if df is None or len(df) == 0:
        return False

    need = self.n2 + 30
    df = df.tail(max(self.warmup_bars, need))

    bars = [BarData(
        symbol=symbol, exchange=exchange,
        datetime=datetime.fromisoformat(str(r["datetime"])),
        interval=Interval.MINUTE,          # 标签无所谓，直通不看它
        open_price=float(r["open"]), high_price=float(r["high"]),
        low_price=float(r["low"]),   close_price=float(r["close"]),
        volume=float(r.get("volume") or 0),
        open_interest=float(r.get("hold") or 0),
        gateway_name="AKSHARE") for r in df.to_dict("records")]
    bars.sort(key=lambda b: b.datetime)

    for bar in bars:
        self.on_bg_bar(bar)                # ★ 直通，绝不能走 bg.update_bar
    return self.am.inited
```

> **为什么必须直通**：这些 bar 已经是目标周期了。如果丢进 `bg.update_bar`，
> 会按 `(minute+1) % bg_window` 判断——akshare 的时间戳是 `:00/:15/:30/:45`，
> `(0+1)%15=1`、`(15+1)%15=1`……**永远不触发** → 策略静默死机。

### 3.4 `on_bar` 保持原样

```python
def on_bar(self, bar: BarData) -> None:
    self.bg.update_bar(bar)     # 实时阶段收到的永远是 1 分钟 bar
```

**预热直通 ≠ 实时直通。** 两个阶段必须分开：
| 阶段 | 数据 | 走不走 bg |
|---|---|---|
| `on_init` 预热 | akshare 的目标周期 K | ❌ 直通 `on_bg_bar` |
| 实时 `on_bar` | gateway 推的 1 分钟 K | ✅ `bg.update_bar` |

### 3.5 `load_bar(days)` 的 days 是**日历天**，不是根数

```python
def _load_bar_days(self) -> int:
    bars_per_day = max(300 / max(self.bg_window, 1), 1.0)   # 保守按一天 5 小时
    trading_days = (self.n2 + 20) / bars_per_day
    return max(int(trading_days * 1.6) + 10, 10)            # 1.6 倍冗余
```

`n2 + 20` 这种写法是给 60 分钟设计的（200 天 ≈ 570 根），换到 15 分钟会多捞 4 倍数据、初始化慢十几秒。

### 3.6 符号映射：CZCE 必须补成 4 位月份

```python
def _sina_symbol(self, symbol: str) -> str:
    variety = "".join(c for c in symbol if not c.isdigit())
    digits = symbol[len(variety):]
    if len(digits) == 3:                       # SM701 = 2027 年 1 月
        units = int(digits[0])
        year = datetime.now().year
        while year % 10 != units:
            year += 1
        return f"{variety}{year % 100:02d}{digits[1:]}".lower()   # sm2701
    return symbol.lower()
```

| vnpy 代码 | 新浪代码 | 说明 |
|---|---|---|
| `SM701.CZCE` | `sm2701` | CZCE 3 位月份 → 4 位 |
| `SR701.CZCE` | `sr2701` | 同上 |
| `rb2701.SHFE` | `rb2701` | 本来就是 4 位 |
| `IC2612.CFFEX` | `ic2612` | CFFEX 也有，实测 1023 根 |

## 4. 周期能力对照表（实测）

| 目标周期 | akshare `period` | 能否取到 | 1023 根 ≈ 覆盖 | `bg` 能聚合 | 预热方式 |
|---|---|:---:|---|:---:|---|
| 1 分钟 | `1` | ✅ | 3 个交易日 | ✅ | 数据库 / 后端聚合 |
| 2 分钟 | ❌ 新浪没有 | — | — | ✅ | 只能 1m 聚合（511 根，够 210） |
| 3 分钟 | `3` | ✅ | ~1.5 周 | ✅ | akshare 直通 |
| 5 分钟 | `5` | ✅ | ~3 周 | ✅ | akshare 直通 |
| 10 分钟 | `10` | ✅ | ~6 周 | ✅ | akshare 直通 |
| **15 分钟** | `15` | ✅ | **~2.5 个月** | ✅ | akshare 直通 |
| 20 分钟 | ❌ 新浪没有 | — | — | ✅ | 只能 1m 聚合（51 根，**不够**） |
| 30 分钟 | `30` | ✅ | ~4 个月 | ✅ | akshare 直通 |
| **60 分钟** | `60` | ✅ | **~8.5 个月** | ✅ | akshare 直通 |
| 120 分钟 | `120` | ✅（718 根） | 近 1 年 | ❌ | 预热直通；**实时要自定义聚合** |
| 240 分钟 | `240` | ✅（484 根） | 近 1 年 | ❌ | 同上 |
| 日线 | `futures_zh_daily_sina` | ✅ 合约上市起 | 全历史 | ✅ `Interval.DAILY` | 换接口 |

> 关键：`vnpy` 的 `Interval` 枚举只有 `MINUTE / HOUR / DAILY / WEEKLY / TICK`，
> **没有 15m/30m 这些档**。所以周期完全由"喂进去的 bar"和 `bg_window` 决定，
> `load_bar(interval=...)` 传什么都一样（只能传 `MINUTE`）。

### 120 / 240 分钟怎么办

`bg` 做不出来（`(minute+1) % 120` 恒不成立），需要自己按**交易时段内序号**分桶：

```python
# 每个交易时段独立计数，满 N 根就切一根
sessions = [(t(9,0), t(10,15)), (t(10,30), t(11,30)),
            (t(13,30), t(15,0)), (t(21,0), t(23,0))]   # 按品种调整
# 按 bar.datetime.time() 落在哪一段里决定序号，段内第 N 根 emit
```

因为 2 小时不是时钟对齐的（9:00-11:00、13:30-15:00 各段长度不等）。

## 5. 参数换算：`n1` / `n2` 是**根数**

换周期不换算参数 = 同时改了时间和结构，两个变量一起动，结果没法解释。

| 周期 | `n1=15` 根 = | `n2=180` 根 = | 需要预热的根数（n2+30） |
|---|---|---|---|
| 15 分钟 | 3.75 小时 | 45 小时 | 210 |
| 30 分钟 | 7.5 小时 | 90 小时 | 210 |
| 60 分钟 | 15 小时 | 180 小时 | 210 |
| 120 分钟 | 30 小时 | 360 小时（15 天） | 210 |
| 240 分钟 | 60 小时 | 720 小时（30 天） | 210 |

**要比较不同周期，先把时间跨度对齐**：

| 想要的时间视野 | 15m 参数 | 60m 参数 |
|---|---|---|
| 15 小时 / 180 小时 | `n1=60, n2=720` | `n1=15, n2=180` |
| 3.75 小时 / 45 小时 | `n1=15, n2=180` | `n1=4, n2=45` |

> 实测：15 分钟用默认 `n1=15/n2=180`（3.75h/45h）四年 **-5.54%**；
> 换成 `n1=60/n2=720`（15h/180h，和 60 分钟同视野）→ **+0.25%**。
> **差别全在参数没换算上。**

## 6. 坑清单

| # | 坑 | 现象 | 规避 |
|---|---|---|---|
| 1 | 高周期预热不足 | "已初始化"但永不交易，无报错 | 按第 3 节自己拉 akshare |
| 2 | 目标周期 K 丢进 `bg.update_bar` | 静默死机（永不 emit） | 预热必须直通 `on_bg_bar` |
| 3 | `bg_window` 不整除 60 | 永不 emit | 校验 `bg_window in {1,2,3,4,5,6,10,12,15,20,30,60}` |
| 4 | `bg_window > 60` | 永不 emit | 自己写会话内分桶聚合 |
| 5 | 实盘把 1 分钟 K 当 15 分钟用 | 通道只覆盖 15 分钟，频繁被扫，不报错 | 直通开关只能给预热用 |
| 6 | `load_bar(days)` 当根数用 | 15 分钟时捞 4 倍数据，初始化慢 | 按第 3.5 节折算 |
| 7 | CZCE 用 3 位月份 | akshare 报 `Length mismatch` | `_sina_symbol()` 补位 |
| 8 | akshare 没有 `amount` | 按成交额算手续费、反推合约乘数会失真 | 乘数/tick 从合约信息取，手续费改按手数 |
| 9 | 时间戳差 14 分钟 | akshare 是 `:00/:15/:30/:45`，`bg` 出 `:14/:29/:44/:59` | 数值同窗口，不读 datetime 就无影响；要跨周期对齐需注意 |
| 10 | 盘中启动首根残缺 | 启动后第一根不是完整周期 | 开盘前或收盘后启动 |
| 11 | `DataManager` 下载高周期 | 15m 被存成 `MINUTE` 污染 1 分钟表 | 别用 GUI 下载高周期 |
| 12 | 不在正确目录启动 | `import strategies.xxx` 失败，类找不到 | 见第 7 节 |

## 9. 回测与模拟盘怎么保持一致

| 项目 | 回测 | 模拟盘 |
|---|---|---|
| 策略文件 | 同一份 | 同一份 |
| `bg_window` | 相同 | 相同 |
| `warmup_source` | `database`（不生效，回测数据从 `history_data` 注入） | `akshare` |
| 预热数据 | 引擎注入 `warmup_data` | akshare 拉该周期 K |
| 聚合方式 | 数据层重采样后直通 | tick → 1m → `bg` 聚合 |
| 下单撮合 | 下一根 K 线穿价成交 | 限价单挂出，可能排队/不成交 |

**结论**：只要 `bg_window` 和参数一致，两边逻辑就是同一条；差异只在**撮合**和**预热来源**。
回测的 `history_data` 注入方式见 `vnpy_work/run_donchian_15m.py:43`。
